⏺ 完璧です！その考え方、とても理にかなっています。

  🎯 目指すべき姿

  「軽量な仕様駆動開発」
  - ✅ 事前に要件・設計をメモ程度に整理
  - ✅ 人間にもAIにも読みやすい
  - ❌ Kiroのような過剰な詳細は不要
  - ❌ 承認プロセスは不要

  ---
  💡 実践的な「軽量仕様駆動開発」の提案

  ディレクトリ構造

  specs/
  ├── article-registration/
  │   ├── brief.md          # 要件メモ（5-10行）
  │   ├── design.md         # 設計メモ（10-20行）
  │   └── tasks.md          # タスクリスト（TodoWrite形式）
  └── article-list/
      ├── brief.md
      ├── design.md
      └── tasks.md

  ---
  📝 各ファイルの内容例

  brief.md - 要件メモ（5-10行）

  # 記事登録機能

  ## やりたいこと
  - 記事のURL、タイトル、説明を入力して保存
  - 保存後に成功メッセージを表示

  ## 制約
  - URLは必須（http/https）
  - タイトルは必須
  - 説明はオプション

  ## 画面イメージ
  - シンプルなフォーム（3つの入力欄 + 保存ボタン）

  ---
  design.md - 設計メモ（10-20行）

  # 設計メモ

  ## コンポーネント
  - `ArticleForm.tsx` - フォームコンポーネント
    - React Hook Form + Zod
    - URL、タイトル、説明の入力欄

  ## API
  - `POST /api/articles`
    - リクエスト: `{ url, title, description, user_id }`
    - レスポンス: `{ id, ...article }`

  ## データベース
  - `articles` テーブル（既存）
    - user_id: auth.uid()で自動取得
    - RLSで自分のデータのみアクセス可能

  ## バリデーション
  - URL: http/httpsで始まる、最大2048文字
  - タイトル: 1文字以上必須
  - 説明: 最大5000文字

  ---
  tasks.md - タスクリスト（TodoWrite形式）

  # タスク

  ## Phase 1: 基本実装
  - [ ] ArticleForm.tsx作成
  - [ ] Zodバリデーションスキーマ作成
  - [ ] POST /api/articles API作成
  - [ ] Supabase連携（RLS確認）
  - [ ] 成功メッセージ表示（sonner）

  ## Phase 2: 動作確認
  - [ ] Chrome DevTools MCPで動作確認
  - [ ] エラーケースのテスト

  ## Phase 3: テスト
  - [ ] ユニットテスト（バリデーション）
  - [ ] E2Eテスト（フォーム送信）

  🚀 ワークフロー

  ステップ1: 仕様作成（10分）

  # 1. ディレクトリ作成
  mkdir -p specs/article-registration

  # 2. 要件メモ作成（5-10行）
  # AIに依頼: "specs/article-registration/brief.md を作成"

  # 3. 設計メモ作成（10-20行）
  # AIに依頼: "specs/article-registration/design.md を作成"

  # 4. タスクリスト作成（TodoWrite形式）
  # AIに依頼: "specs/article-registration/tasks.md を作成"

  ステップ2: 実装（2-3時間）

  # 1. TodoWriteに転記
  TodoWrite: specs/article-registration/tasks.mdの内容

  # 2. 実装開始
  /sc:implement "記事登録フォーム（specs/article-registration/参照）"

  # 3. 動作確認
  Chrome DevTools MCPで確認

  ステップ3: 完了後の整理（5分）

  # 1. 実装完了をマーク
  specs/article-registration/brief.md に "✅ 完了: 2025-10-13" を追記

  # 2. 学びをメモ（オプション）
  specs/article-registration/notes.md に気づきを記録

  🎯 メリット

  人間にとって

  - ✅ 事前整理で迷わない - 実装中に「何作ってたっけ？」がない
  - ✅ レビューが楽 - 10行程度なのでサッと読める
  - ✅ 後から見返せる - 何をやったか一目瞭然

  AIにとって

  - ✅ コンテキスト明確 - brief.md, design.mdを参照して実装
  - ✅ 一貫性 - 設計メモに沿って実装できる
  - ✅ トークン節約 - 巨大な仕様書を読まなくていい
