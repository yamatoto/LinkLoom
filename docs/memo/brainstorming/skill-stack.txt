  1. React Hook Form ⭐ 強く推奨

  用途: フォーム管理

  なぜ必須級？
  - 記事登録フォーム、編集フォームが複数ある
  - Zodとの統合が完璧（@hookform/resolvers/zod）
  - パフォーマンス◎（非制御コンポーネント）
  - バリデーションエラー表示が簡単

  使用例:
  import { useForm } from 'react-hook-form'
  import { zodResolver } from '@hookform/resolvers/zod'
  import { z } from 'zod'

  const articleSchema = z.object({
    title: z.string().min(1, '必須です'),
    url: z.string().url('有効なURLを入力してください'),
    tags: z.array(z.string()).min(1),
  })

  const { register, handleSubmit, formState: { errors } } = useForm({
    resolver: zodResolver(articleSchema)
  })

  代替案: なし（React標準のフォーム管理は複雑すぎる）

  2. date-fns or Day.js 🕐 推奨

  用途: 日付フォーマット

  なぜ必要？
  - 記事の投稿日表示（例: "2025年10月5日", "3日前"）
  - 日本語ロケール対応
  - 軽量（date-fns: tree-shakable, Day.js: 2KB）

  使用例:
  import { format, formatDistanceToNow } from 'date-fns'
  import { ja } from 'date-fns/locale'

  // "2025年10月5日"
  format(new Date(), 'yyyy年MM月dd日', { locale: ja })

  // "3日前"
  formatDistanceToNow(new Date(article.created_at), {
    locale: ja,
    addSuffix: true
  })

  推奨: date-fns（Next.jsと相性◎、tree-shakable）

  3. clsx + tailwind-merge 🎨 必須

  用途: className管理

  なぜ必須？
  - TailwindのclassNameを条件付きで結合
  - 重複クラスの競合を解決（cnユーティリティ）

  使用例:
  import { clsx } from 'clsx'
  import { twMerge } from 'tailwind-merge'

  export function cn(...inputs: ClassValue[]) {
    return twMerge(clsx(inputs))
  }

  // 使用
  <div className={cn(
    "p-4 rounded",
    isActive && "bg-blue-500",
    "hover:bg-blue-600" // 重複してもマージされる
  )} />

  shadcn/uiのデフォルト: 既に含まれている想定（lib/utils/cn.ts）

  4. sonner 🔔 推奨

  用途: トースト通知

  なぜ必要？
  - 記事保存成功/失敗の通知
  - 削除確認のフィードバック
  - ユーザビリティ向上

  使用例:
  import { toast } from 'sonner'

  toast.success('記事を保存しました')
  toast.error('保存に失敗しました')

  代替案: react-hot-toast（sonnerの方がモダン、shadcn/ui推奨）

  🤔 不要なライブラリ（よくある誤解）

  ❌ 不要: Lodash

  - 理由: ES2015+の配列メソッドで十分（.map, .filter, .reduce）
  - 例外: 深いオブジェクトの比較が頻繁にある場合のみlodash-esを部分的に

  ❌ 不要: Moment.js

  - 理由: 重い、メンテナンス終了
  - 代替: date-fns or Day.js

  ❌ 不要: Axios

  - 理由: Fetch APIで十分、TanStack Queryがラップする
  - Next.jsは標準でFetch拡張あり

  ❌ 不要: Redux Toolkit

  - 理由: Zustand + TanStack Queryで十分
  - 小〜中規模アプリにはオーバースペック
