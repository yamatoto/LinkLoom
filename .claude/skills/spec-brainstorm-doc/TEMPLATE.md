## ドキュメント化のベストプラクティス

### 良いドキュメントの特徴

1. **具体的**: 抽象的な説明より具体例を含む
2. **簡潔**: 必要な情報に絞る
3. **構造化**: セクションが明確
4. **決定理由**: なぜその判断をしたか記載
5. **トレードオフ**: メリット・デメリット両方記載
6. **将来を考慮**: 拡張性や変更の余地を記載

### セクションの取捨選択

すべてのセクションを埋める必要はありません。議論の内容に応じて、関連するセクションのみを使用してください。

**最小限のドキュメント**:
- 背景・目的
- 要件定義
- 設計方針
- 決定事項

**詳細なドキュメント**:
- 上記すべて + 検討した代替案 + テスト戦略 + 実装計画

### 会話履歴の記録

長い会話の場合、すべてを記録する必要はありません。以下に絞って記録：

- **重要な質問と回答**: 判断の分岐点になった会話
- **決定事項**: 何を決めたか
- **理由**: なぜそう決めたか
- **トレードオフ**: どんな選択肢があり、なぜそれを選んだか

### 更新・メンテナンス

ドキュメントは一度書いたら終わりではありません：

- 実装中に判明したことを追記
- 変更があれば更新
- 定期的にレビュー
