# 軽量仕様駆動開発 - specs/

このディレクトリは、LinkLoomプロジェクトの各機能の仕様を管理します。

## 📁 ディレクトリ構造

```
specs/
└── [feature-name]/
    ├── brief.md      # 概要（5-10行）
    ├── design.md     # 設計メモ（10-20行）
    └── tasks.md      # タスク一覧（TodoWrite形式）
```

## 📝 各ファイルの役割

### brief.md（5-10行）

**目的**: 機能の全体像を5分で理解できるようにする

**含めるべき内容**:

- 何を作るか（1文）
- なぜ必要か（1文）
- どこに実装するか（ファイルパス）
- 主要機能（箇条書き3-5個）

### design.md（10-20行）

**目的**: 実装前に設計の方向性を明確にする

**含めるべき内容**:

- コンポーネント構成
- データフロー
- 技術選択（ライブラリ、パターン）
- 考慮すべき制約

### tasks.md

**目的**: 実装タスクを追跡可能にする

**含めるべき内容**:

- フロントエンド/バックエンド/テストのタスク
- チェックボックス形式（`- [ ]`）
- 優先順位（高/中/低）

## 🎯 使い方

### 1. 新機能を始める

```bash
# 1. 仕様ディレクトリ作成
mkdir -p specs/[feature-name]

# 2. Claude Codeに依頼
「[feature-name]の簡易仕様を作成してください」

# 3. 仕様を確認・編集（5分以内）
# 4. 実装開始
```

### 2. 既存機能を改善する

```bash
# 1. 既存の仕様を確認
cat specs/[feature-name]/brief.md

# 2. 必要に応じてdesign.mdやtasks.mdを更新

# 3. 実装
```

## ✅ 良い仕様の例

**brief.md**:

```markdown
# 記事登録フォーム

**何を作るか**: URL入力で記事を素早く登録できるフォーム

**なぜ必要か**: ユーザーが見つけた記事をすぐに保存したいため

**どこに実装するか**: `/articles/new` ページ

**主要機能**:

- URL入力フィールド
- 自動メタデータ取得
- タグ選択
```

**design.md**:

```markdown
# 設計メモ

## コンポーネント

- ArticleForm（メイン）
- UrlInput（URL入力）
- TagSelector（タグUI）

## データフロー

1. URL入力
2. メタデータ取得（API）
3. フォーム自動入力
4. DB保存

## 技術

- Zod: バリデーション
- React Hook Form: フォーム管理
```

## ❌ 避けるべきこと

- ❌ 詳細すぎるコード例（実装で書けばいい）
- ❌ 完璧を求めすぎる（実装しながら更新可能）
- ❌ 形式に固執する（読みやすければOK）
- ❌ 長大なドキュメント

## 💡 ヒント

- **5分ルール**: 仕様作成は5-10分以内に終わらせる
- **更新OK**: 実装中に気づいたことは随時追記
- **AI活用**: Claude Codeに「簡易仕様を作成して」と依頼
- **柔軟性**: プロジェクトに合わせて自由にカスタマイズ
