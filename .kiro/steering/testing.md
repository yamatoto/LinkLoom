# テストガイドライン - Steering

このファイルは、LinkLoomプロジェクトにおけるテストコード作成の共通ルールを定義します。

## 📋 詳細ガイドライン

**包括的なテストガイドラインは @tests/README.md を参照してください。**

このSteeringファイルには、AIが常に守るべき最重要原則のみを記載します。

---

## 🎯 コア原則（必須遵守）

### 1. 静的解析エラーゼロで作業完了

**絶対ルール:**

- 作業完了前に必ず `npm run lint` と `npm run tsc` を実行
- すべてのlintエラー・TypeScriptエラーを修正してから完了報告
- 「エラーは後で修正してください」という対応は厳禁
- プロダクション品質を維持するための絶対的な品質ゲート

### 2. テストファイル配置

**配置ルール:**

```
tests/
├── unit/              # ユニットテスト（関数・コンポーネント単体）
│   ├── components/    # Reactコンポーネント
│   ├── hooks/         # カスタムフック
│   └── lib/           # ユーティリティ関数
├── e2e/               # E2Eテスト（ユーザーシナリオ）
└── mocks/             # モックデータ・スタブ
```

**禁止事項:**

- ソースコードと同じディレクトリにテストファイルを配置しない
- プロジェクトルートに散らばったテストファイルを作成しない

### 3. テスト品質基準

**すべてのテストコードは以下を満たす必要がある:**

1. **AAA パターン準拠**: Arrange（準備） → Act（実行） → Assert（検証）
2. **明確なテスト名**: `should [期待する動作] when [条件]` 形式
3. **独立性**: テスト間で状態を共有しない、順序に依存しない
4. **実装詳細の隠蔽**: 内部実装ではなく、公開APIや振る舞いをテスト
5. **適切なモック**: 必要最小限、外部依存のみモック化

### 4. テスト実行タイミング

**必須実行タイミング:**

- コミット前: `npm run test` + `npm run lint` + `npm run tsc`
- 実装完了時: 関連テストの実行確認
- リファクタリング時: 既存テストが全てパスすることを確認

---

## 🚫 禁止事項

1. **テストをスキップしない**
   - `test.skip`, `describe.skip` の使用禁止（一時的なデバッグを除く）
   - コミット前に必ずすべてのスキップを解除

2. **テストを無効化しない**
   - テストをコメントアウトして "動くようにする" 対応は厳禁
   - 失敗するテストは原因を調査して修正する

3. **低品質なテストを書かない**
   - アサーションのないテスト（smoke testを除く）
   - 常にパスするテスト（意味のないアサーション）
   - 不安定なテスト（flaky test）を放置しない
