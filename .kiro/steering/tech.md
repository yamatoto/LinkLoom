# 技術スタック

**包含モード**: Always - 技術的制約はすべてのコード生成に影響

## アーキテクチャ

**現在の状態**: グリーンフィールドプロジェクト - アプリケーションアーキテクチャ未定義

**フレームワーク**: Claude Code統合によるKiro仕様駆動開発

**決定プロセス**: 技術選択は仕様設計フェーズ中に以下に基づいて行われます:
- 機能要件
- パフォーマンスニーズ
- スケーラビリティ考慮事項
- チームの専門知識
- 統合要件

## 開発環境

### 必須ツール
- **Claude Code**: AI駆動開発環境
- **Git**: バージョン管理（リポジトリ初期化済み）
- **Kiro Framework**: 仕様駆動開発コマンド

### Kiroコマンド構造
```
/kiro:steering          - プロジェクトSteeringドキュメント更新
/kiro:spec-init         - 新規機能仕様の初期化
/kiro:spec-requirements - 要件ドキュメント生成
/kiro:spec-design       - 技術設計作成
/kiro:spec-tasks        - 実装タスク生成
/kiro:spec-status       - 仕様進捗確認
/kiro:spec-impl         - 実装タスク実行
/kiro:validate-design   - インタラクティブ設計検証
/kiro:validate-gap      - 実装ギャップ分析
/kiro:steering-custom   - カスタムSteeringドキュメント作成
```

## 開発ワークフロー

### 仕様駆動開発プロセス
1. **Steering更新**: `/kiro:steering`（必要に応じて）
2. **仕様**: `/kiro:spec-init [説明]`
3. **要件**: `/kiro:spec-requirements [feature]`
4. **設計**: `/kiro:spec-design [feature]`（承認された要件が必要）
5. **タスク**: `/kiro:spec-tasks [feature]`（承認された設計が必要）
6. **実装**: `/kiro:spec-impl [feature] [task-numbers]`
7. **検証**: `/kiro:validate-design` および `/kiro:validate-gap`

### 品質ゲート
- 設計前に要件を承認する必要がある
- タスク生成前に設計を承認する必要がある
- 実装前にタスクを明確に定義する必要がある
- 該当する場合、実装はTDD方法論に従う

## コード品質基準

### 一般原則
- **TypeScript/型安全性**: 該当する場合、型付き言語を優先
- **テスト**: 適切なテストフレームワークによる包括的なテストカバレッジ
- **リンティング**: 一貫したコードスタイルと品質チェック
- **ドキュメント**: 明確なインラインドキュメントとREADME更新

### セキュリティ考慮事項
- **入力検証**: すべてのユーザー入力を検証
- **認証/認可**: 適切なセキュリティ対策を実装
- **環境シークレット**: 機密データをバージョン管理にコミットしない
- **HTTPS**: 本番環境で安全なプロトコルを使用

## 技術決定フレームワーク

仕様設計中に技術を選択する際:

1. **要件整合性**: 技術は機能要件を満たすか？
2. **パフォーマンス**: 予想される負荷と応答時間要件を処理できるか？
3. **スケーラビリティ**: 予想される成長パターンをサポートするか？
4. **保守性**: 優れたコミュニティサポートを伴う十分なドキュメントがあるか？
5. **統合**: 他の選択された技術とどの程度うまく機能するか？
6. **チームの専門知識**: 必要なスキルを持っているか、または取得できるか？
