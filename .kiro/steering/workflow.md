# 開発ワークフロー - Steering

このファイルは、LinkLoomプロジェクトにおける開発ワークフローの共通ルールを定義します。

## タスク管理ルール

### tasks.mdの更新義務

**すべてのセッションで、タスク実装完了時には必ずtasks.mdを更新すること。**

#### ルール詳細:

1. **タスク完了時の即時更新**
   - タスクの実装が完了したら、すぐに該当タスクにチェックマーク `[x]` をつける
   - サブタスクがある場合は、親タスクとサブタスクの両方にチェックをつける

2. **実装場所の記録**
   - チェックマーク追加時に、実装したファイルと行番号を記録する
   - フォーマット: `_実装場所: \`path/to/file.ts:line_numbers\`_`
   - 複数ファイルの場合はカンマ区切り

3. **詳細実装ステータスの記録**
   - 各サブタスクの項目に ✅ マークを追加
   - 部分的な実装や変更がある場合は ⚠️ と説明を追加

#### 例:

```markdown
- [x] 7. エラーハンドリングとトースト通知を実装
- [x] 7.1 認証エラーシナリオのハンドリングを追加
  - ✅ Google認証キャンセル時のトースト通知実装
  - ✅ ネットワークエラー時のエラー表示
  - ✅ Supabase接続エラー時のエラーメッセージ表示
  - ✅ セッション期限切れ時の自動リダイレクト処理
  - _Requirements: 6.1（エラーハンドリング）_
  - _実装場所: `src/components/auth/GoogleLoginButton.tsx:16-57`, `src/hooks/useAuth.ts:82-98`_
```

### 実装前の確認

タスク実装前に以下を確認:

1. **依存タスクの完了確認**
   - tasks.mdの「タスク実行の注意事項 > 依存関係」セクションを参照
   - 依存するタスクが完了していることを確認

2. **要件の理解**
   - tasks.mdの該当タスクの要件を熟読
   - 不明点があれば質問する

3. **設計仕様の参照**
   - `.kiro/specs/[feature-name]/design.md` を参照
   - 技術設計に従って実装する

## コミット前のチェックリスト

コミット前に必ず以下を実行:

1. ✅ **tasks.mdの更新確認**
   - 実装したタスクにチェックマークがついているか
   - 実装場所が記録されているか

2. ✅ **静的解析の実行**
   ```bash
   npm run lint && npm run tsc
   ```
   - ESLintエラーゼロを確認
   - TypeScriptエラーゼロを確認

3. ✅ **動作確認**
   - Chrome DevTools MCPで実際の動作を確認
   - エラーが発生しないことを確認

4. ✅ **コードレビュー**
   - `/sc:analyze --focus architecture` でアーキテクチャレビュー実行
   - 指摘事項があれば修正

## セッション管理

### セッション開始時

```bash
/sc:load
```

### セッション中

- 30分ごとに進捗を確認
- 重要な実装完了時にtasks.mdを更新

### セッション終了時

```bash
/sc:save
```

## 品質基準

### プロダクション品質の定義

すべての実装は以下を満たす必要がある:

1. **機能要件**: 仕様通りに動作する
2. **型安全性**: TypeScriptエラーゼロ
3. **コード品質**: ESLintエラーゼロ
4. **セキュリティ**: 機密情報の漏洩なし
5. **パフォーマンス**: 無駄なレンダリングなし
6. **可読性**: コメントと構造が明確

### レビュー基準

コードレビュー (`/sc:analyze`) で以下を評価:

- 責務分離の適切性
- 可読性・保守性・変更容易性
- React/Next.jsの最新仕様準拠
- TypeScript型の適切性
- パフォーマンスの懸念点
- セキュリティの懸念点

スコア **9.0/10以上** でコミット可能と判断。

---

**重要**: このルールはすべてのセッション、すべての開発者（AI・人間問わず）に適用されます。
